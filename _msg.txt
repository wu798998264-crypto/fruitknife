fix: 下载全失败 —— 服务端拉黑设备指纹 + 改用 bytevc2 加密

## 现象
2026-11-09 起，所有下载全部失败，日志报
`requests.exceptions.JSONDecodeError: Expecting value: line 1 column 1 (char 0)`。
搜索、解析正常（走网页与 sinfonlinec 接口），只有下载（sinfonlineb）挂。

## 根因（两层，互相独立）

### ① 服务端拉黑了硬编码的假设备指纹
`multi_video_model` 接口对**已注册过的设备指纹**放行，对编造的指纹
返回 `HTTP 200 + Content-Type: application/json + 响应体长度 0`
—— 不是错误码，所以 `r.json()` 抛 JSONDecodeError，极易误判为网络问题。

原代码硬编码：
    device_id  = 11223344556677889900   ← 编造的
    install_id= 99887766554433221100   ← 编造的
11-05 还能用，11-09 起被拉黑。

**定位方法**：把搜索 API（一直能用）的那套设备指纹整套搬到播放器 API
→ 立刻命中 vid。再逐项退回做最小差异定位，确认**唯一致命项就是
device_id / install_id**，cdid、channel、device_type、version_code
退回旧值都不影响。

**修复**：新增 `app/devices.py` 设备指纹池（真实注册过的），
下载时逐组尝试、自动轮换 —— 服务端再拉黑某组时能自动切换，
而不是让用户看到「全部失败」。

### ② 服务端把大部分清晰度改成了 bytevc2
`video_model` 升级到 v3 结构，各档加密方式不再一致：

| 清晰度 | gear_des_key | 能否下载 |
|---|---|---|
| 360p / 480p / 540p / 720p | `2:bytevc2` | ✗ ffmpeg 不认识 bvc2 |
| 1080p | `2:h265_hvc1` | ✓ 标准 HEVC |

bytevc2 是字节私有加密 HEVC，容器里 codec tag 是 `bvc2`(0x32637662)，
ffmpeg 报 `Could not find tag for codec none`。
**修复**：选档时读 gear_des_key 避开 bytevc2，自动回退到标准 HEVC 那一档。

### 附带的结构变化（都已兼容）
- `fallback_api` 从字符串变成 dict（多包一层）→ 取 `["fallback_api"]`
- `video_model.video_list` 变成 list，每项带 `video_meta.definition`（清晰度）
- `main_url` 在 multi_video_model 侧是明文 URL，但那是 bytevc2 流，ffmpeg 解不了
  → 仍走 fallback_api 那条（base64+AES 密文，解密后是标准 CENC 流）
- 内容密钥：`encrypt_info.encryption_method = cenc-aes-ctr` → **key 就是 kid**
  （新增优先用 kid，没有才退回旧的 derive_content_key(spade_a)）

## 其他
- 失败原因分类：bytevc2 → `bytevc2_unsupported`，不再只报 ffmpeg_fail
- 任务完成时若实际清晰度与用户选择不同，界面上明确提示
  （「540p 不可用，实际 1080p」）
- `app/devices.py` 补进 hongguo.spec 的 datas（否则冻结包里缺失）
- `batch_downloader.py` 既可能作为包内模块、也可能被当脚本直接启动，
  `from app import devices` 两种都要兜住（importlib 按路径加载）

## 验证（冻结包内，走完整下载链路）
API 200 → 540p 判定为 bytevc2 → 自动回退 1080p → 用 kid 解密 →
ffmpeg rc=0 → 26.79MB / hevc / hvc1 / 1920x1080 / 339.685s
